# Paid-path offline rehearsal — 2026-11-02

The existing owner-signed production path now has a single cross-module integration
test: frontend/src/lib/moneyJourney.test.ts. Its receipt fixtures were generated by
scripts/generate-money-rehearsal.cjs in the contracts prototype branch using actual
canonical GSTD wallet code in TON Sandbox. They are explicitly NOT mainnet payments.

The test exercises real deposit and withdrawal API handlers, raw transaction parsing,
canonical sender-wallet resolution, backing reconciliation, paid inference orchestration,
failure refunds, exact 85/10/5 accounting, zero-fee claims, duplicate requests and
independently verified recipient receipts. It conserves100GSTD as90payer+8.5executor+
1protocol+0.5reserve; after executor withdrawal, custody and allocated liabilities
both equal91.5. The executor's8.5 is delivered in the simulated canonical token transfer.

Mocked boundaries: authenticated wallet-session lookup, model executor response,
public chain indexer HTTP, and the nonproduction in-memory KV backend. TON login
proof, node authentication, canonical wallet execution and production Redis behavior
have separate tests/checks; this integration test does not establish their live operation.

This test does not sign or broadcast a real transaction, add production balances,
alter backing, enable a new payout mode, or establish independent-physical-node
resilience. Actual wallet signing, mainnet indexer timing, gas costs and a funded
deposit/work/payout remain a real acceptance gate.

Autonomous escrow/account prototypes are separate in contracts PR5 and remain
unconnected to this ledger. They require reviewed migration and wallet UI integration;
their source presence must not be described as deployed autonomous withdrawals.

Run: cd frontend && npx vitest run src/lib/moneyJourney.test.ts
